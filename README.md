# 고교 진로·선택과목 설계 대시보드 (jinro-dash)

2022 개정 교육과정·고교학점제 기준으로 **내 학교·참조군 비교 → 생기부 진단 → 희망 계열·학과 → 과목·탐구 설계 → 상담 리포트**까지
한 흐름으로 이어 주는 정적 웹앱입니다. 서버·로그인·개인정보 수집이 없습니다.

진단을 먼저 두는 이유는, 거기서 나온 **보완점이 이후의 계열·과목·탐구 주제 선택에 그대로 반영**되기 때문입니다.
(진단을 건너뛰어도 설계는 가능합니다.)

- 현재 수록: 서울 강남구 14개교 + 광진구 1개교 (총 15개교), 계열 4개, **세부 학과 34개**, 탐구자료 10개 과목
- 참조 바스켓: 서울대 수시 다수 배출 자사고 5 + 일반고 6 (학교알리미 공시 집계)
- 기술: 순수 HTML + CSS + 바닐라 JS (빌드 과정 없음) · GitHub Pages 배포 전제
- **코드와 데이터가 분리되어 있습니다.** 학교를 추가할 때 코드는 건드리지 않습니다.

---

## 1. 배포하기 (GitHub Pages)

1. 이 저장소를 GitHub에 올립니다.
2. `Settings → Pages → Build and deployment → Source: Deploy from a branch`
3. Branch를 `main` / 폴더를 `/ (root)`로 지정하고 저장합니다.
4. 1~2분 뒤 `https://<계정>.github.io/jinro-dash/` 주소가 생깁니다. 이 주소를 배포하면 됩니다.

## 2. 로컬에서 실행하기 (중요)

`index.html`을 **더블클릭해서 열면 동작하지 않습니다.** 브라우저 보안 정책(`file://`) 때문에
JSON 데이터를 읽을 수 없기 때문입니다. 아래 중 하나로 실행하세요.

```bash
# Python이 설치되어 있다면 (대부분의 Mac/Linux)
python3 -m http.server 8000

# Node.js가 설치되어 있다면
npx serve .
```

그다음 브라우저에서 `http://localhost:8000` 으로 접속합니다.

## 3. 새 학교 추가하는 법 (코드 수정 없음)

### ① 학교 JSON 파일을 만든다

`data/schools/<시도영문>/<시군구영문>/<학교ID>.json` 경로에 아래 형식으로 만듭니다.
기존 파일 하나를 복사해서 값만 바꾸는 것이 가장 안전합니다.

```json
{
  "schemaVersion": "4.0",
  "schoolId": "seoul-gangnam-example",
  "name": "○○고등학교",
  "schoolType": "일반고",
  "region": { "sido": "서울특별시", "sigungu": "강남구" },
  "source": "학교 교육과정 편제표(2022 개정) / 학교알리미",
  "programs": ["자율탐구 프로그램", "지역대학 연계 R&E"],
  "professionalSubjects": [
    { "name": "고급물리학", "track": "과학 계열 심화", "grade": 3 }
  ],
  "tracks": [
    {
      "trackId": "ilban",
      "label": "일반과정",
      "phases": [
        {
          "phaseId": "g2",
          "label": "2학년 (택5 + 택5, 30학점)",
          "grade": 2,
          "requiredPickCount": 10,
          "totalCredits": 30,
          "options": [
            { "subject": "미적분Ⅱ", "area": "수학", "category": "진로선택", "credits": 3 }
          ]
        }
      ]
    }
  ],
  "achievement": null,
  "gradeStats": {}
}
```

**값 규칙**

| 항목 | 규칙 |
|---|---|
| `schoolId` | 영문·숫자·하이픈. 전체 학교 중 **중복 금지**. `regions.json`의 값과 반드시 일치. |
| `schoolType` | `일반고` / `자율형사립고` / `자율형공립고` / `특목고(외국어고)` / `특성화고` 등 |
| `category` | `공통과목` / `일반선택` / `진로선택` / `융합선택` **넷 중 하나만** (오타 나면 검증 스크립트가 잡아냅니다) |
| `grade` | `2`, `3`, 또는 학년 공통 구간이면 `null` |
| `requiredPickCount` | 그 구간에서 학생이 골라야 하는 과목 수 |
| `professionalSubjects` | 편제표에 적힌 명칭을 **그대로** 넣습니다. 없으면 `[]` |
| `gradeStats` | **운영자 입력 전용.** 비워 두면 화면에 "데이터 미입력"으로 표시됩니다. 추정값을 임의로 채우지 마세요. |
| `subjectAchievement` | 학교알리미 **과목별** 원점수평균·A·B 비율. 학년/학기별 카드로 표시됩니다. 없으면 `null` |
| `metrics` | 참조 바스켓 비교축(국·수·영·과·사 평균, `coreAvg`, `coreArate`, `elective23`). 없으면 비교표에 "미입력" |
| `creditPlan` | 학점배당표 기반 **공통과목 포함 전 과목**과 택N 안내. 없으면 선택과목 편제만 표시 |

### ② 지역 인덱스에 한 줄 등록한다

`data/regions.json`의 해당 시·군·구 `schools` 배열에 한 줄 추가합니다.

```json
{ "schoolId": "seoul-gangnam-example", "name": "○○고등학교", "type": "일반고",
  "path": "schools/seoul/gangnam/seoul-gangnam-example.json", "hasAchievement": false }
```

### ③ 검사한다

```bash
node tools/validate.mjs
```

`✅ 모두 정상입니다.`가 나오면 끝입니다. 오류가 나오면 **어느 파일의 무엇이 문제인지** 알려 줍니다.

> 새 시·도나 시·군·구를 추가할 때는 `regions.json`에 `{ "name": "부산광역시", "dir": "busan", "sigungu": [...] }`
> 형태로 넣고, 폴더 이름은 `dir` 값과 같은 영문으로 만듭니다.

## 4. 새 계열 추가하는 법

1. `data/majors/<계열ID>.json`을 만듭니다 (`data/majors/eng.json` 복사 권장).
2. `data/majors/index.json`의 `majors` 배열에 한 줄 추가합니다.

주요 항목: `recommendedSubjects`(권장 과목), `roadmap`(학기별 배치), `guidance`(진학 방향),
`diagnosisKeywords`(생기부 진단에서 진로역량을 판정할 때 쓰는 키워드), `departments`(하위 학과).

> `recommendedSubjects`에 **이름으로** 적힌 과목은 교과군과 무관하게 권장으로 인정됩니다
> (예: 사회계열의 `심화 영어`, `데이터 과학`). 반면 학과의 `recommendKeywords`는
> 그 학과의 `focusAreas` 안에서만 적용됩니다.

## 4-1. 세부 학과 (탐구 주제 풀)

계열(`majors/`)이 큰 방향이라면, 학과(`programs/`)는 **탐구 주제를 직접 쥐고 있는 단위**입니다.
학과를 고르면 그 학과의 주제 풀로 설계가 생성되고, 주제마다 배경·핵심질문·방법·산출물·세특연결·확장이 붙습니다.

**현재 34개 학과**

| 계열 | 학과 |
|---|---|
| 공학·의약·AI | 기계·전기전자·컴퓨터·화학공·신소재·반도체공학과, 의예·치의예과, 약학·간호학과 |
| 자연·이학 | 수학·통계학·물리학·천문우주학·화학·생명과학·지구환경과학·해양학과 |
| 사회·상경 | 경영·경제·정치외교·행정·법학·사회학·언론정보·심리학과 |
| 인문·어문 | 국어국문·영어영문·독어독문·중어중문학과, 사학·철학·고고미술사학·교육학과 |

### 학과 파일은 직접 고치지 말고 빌드하세요

`data/programs/*.json`은 **생성물**입니다. 소스는 다음 세 파일입니다.

```
tools/topics/catalog.mjs    학과 정의(중심 교과군·권장 키워드·영역 매핑) + 학과 고유 주제
tools/topics/shared.mjs     계열 그룹별 공통 주제 풀 (engineering·medical·natural·social·humanities)
tools/extra-topics.mjs      기존 4개 학과 보강 주제
```

```bash
node tools/build-programs.mjs <프로토타입 index.html>   # data/programs/ 전체 재생성
node tools/validate.mjs                                # 검사
```

빌드는 계열(`majors/*.json`)의 `departments`도 학과 이름과 자동으로 맞춰 줍니다.
(이름이 어긋나면 같은 학과가 "준비 중" 카드로 한 번 더 그려집니다.)

**새 학과 추가** — `tools/topics/catalog.mjs`의 `CATALOG` 배열에 항목 하나를 넣고 빌드하면 끝입니다.
고유 주제(`own`)를 안 넣어도 그룹 공통 주제로 바로 동작합니다.

### 학과 파일 형식 (생성 결과)

```json
{
  "programId": "medicine", "name": "의예과", "majorId": "eng", "field": "의약계열",
  "focusAreas": ["수학", "과학"],
  "recommendKeywords": ["미적", "기하", "화학", "생명"],
  "areaMap": { "생명": ["생명", "세포", "물질대사", "유전"], "화학": ["화학", "반응"] },
  "topicPools": {
    "생명": [{
      "title": "항생제 내성의 진화적 메커니즘과 대사 경로",
      "background": "…", "question": "…",
      "method": ["…", "…"], "output": "탐구보고서 + 발표",
      "setuk": "생명과학Ⅱ 세특: …", "extend": "…",
      "tags": ["data"]
    }]
  },
  "resources": [{ "kind": "도서", "title": "…", "author": "…", "publisher": "…", "find": "교보문고 검색", "why": "…" }]
}
```

- `focusAreas`는 **이 학과가 중심으로 보는 교과군**입니다. 여기 없는 교과군의 과목은
  권장 판정과 주제 배정에서 제외됩니다. **계열이 뒤섞이는 것을 막는 1차 안전장치**입니다.
  (이게 없으면 `recommendKeywords`의 짧은 단어 '세계'·'문화'가 "화학 반응의 세계"·"과학의 역사와 문화" 같은
  이과 과목에 걸려 사회계열 설계에 이과 과목이 섞입니다.)
- `areaMap`은 **과목명 → 탐구 영역** 매핑입니다. 여러 영역에 걸리면 **가장 긴 키워드**로 매칭된 영역을 씁니다.
  키워드로 못 찾으면 그 과목의 교과군 이름과 같은 영역을 씁니다. 그래도 없으면
  **주제를 억지로 붙이지 않고** 비워 둡니다.
- `tags: ["data"]`를 단 주제는 생기부 진단에서 "정량적 데이터 근거 보완"이 뜰 때 **우선 노출**됩니다.
- **한 주제는 한 과목에만 배정**됩니다. 같은 영역에 남은 주제가 없으면 다른 영역에서 끌어오지 않고
  "주제를 배정하지 않은 과목"으로 묶어 안내합니다. (영역을 넘나들면 "세계사 — 표집 편향 탐구" 같은
  어긋난 조합이 생깁니다. 학생이 카드의 🔄를 누르면 그때만 다른 영역까지 후보로 넓힙니다.)
- 따라서 **주제 수가 곧 설계 가능한 과목 수**입니다. 학생이 보통 8~12과목을 고르므로
  학과당 12개 이상을 권합니다. 주제 보강은 `tools/extra-topics.mjs`에 넣고 재생성하세요.

## 4-2. 참조 바스켓 바꾸는 법

`data/reference-groups.json` 하나만 고치면 됩니다.

```json
{ "groupId": "basket-jasa", "label": "자사고 참조군", "schoolType": "자사고",
  "members": ["민사고", "외대부고"],
  "byArea": { "국어": { "avg": 88.9, "A": 68.5 } },
  "coreAvg": 86.3, "coreArate": 67.0, "elective23": 115.4 }
```

비교 대상 학교의 `metrics`가 없으면 그 학교는 비교표에 "미입력"으로 뜹니다. 값을 지어내지 않습니다.

> 참조군 구성 학교가 수록 학교 목록에도 있으면(예: 영동고), 그 학교를 선택했을 때
> **"내 학교가 참조군에 포함되어 있습니다"** 안내가 자동으로 뜹니다.
> 그 열의 평균에는 자기 학교 값이 섞여 있으므로, 상대 위치는 다른 유형 참조군 열로 읽어야 합니다.

## 5. 탐구 자료(도서·논문) 추가하는 법

`data/research/subjects.json`의 `subjects`에 과목명을 키로 추가합니다.

```json
"생명과학": {
  "field": "의약·자연", "subtitle": "미생물·유전 중심 탐구",
  "topics": ["…"],
  "design": "<b>탐구 질문</b> … <br><b>가설</b> …",
  "books":  [{ "t": "정확한 제목", "a": "저자", "p": "출판사" }],
  "papers": [{ "t": "정확한 논문 제목", "a": "게재지·연도", "s": "RISS", "u": "https://…" }]
}
```

> ⚠️ **환각 방지 규칙** — 도서·논문은 **검색으로 실재를 확인한 것만** 넣습니다.
> 존재하지 않는 제목·저자·DOI를 만들어 넣으면 안 됩니다. 개수를 못 채우면 비워 두는 편이 낫습니다.
> 확인이 안 되는 항목은 검증 스크립트가 경고로 알려 줍니다.

## 6. 성적 데이터에 대한 주의

- `achievement`(학업성취)는 **학교알리미 공시자료** 기준의 **학교 전체 교과군 평균**입니다. 개인 성적이 아닙니다.
- 학교별 "과목 평균 성적대"(`gradeStats`)는 공개 데이터가 아닙니다. **운영자가 직접 입력한 값만** 표시하며,
  값이 없으면 화면에 `데이터 미입력`으로 나옵니다. 추정값을 넣을 때는 `confidence: "운영자입력"`으로 표시해
  공개 데이터와 시각적으로 구분되게 합니다.
- **어떤 경우에도 성적 데이터를 임의로 만들어 넣지 않습니다.**

## 7. 개인정보 (생기부 기능)

- 생기부는 **미성년자의 민감 개인정보**입니다. STEP 3(생기부 진단)은 동의 화면을 반드시 거칩니다.
- 업로드/붙여넣은 생기부는 **브라우저 안에서만** 처리되며 서버로 전송되지 않습니다.
- 이름·학번·주민등록번호·전화번호·이메일 패턴은 분석 전에 **자동 마스킹**됩니다.
- 저장되는 것은 분석 요약이며, 원문은 사용자가 명시적으로 체크했을 때만 그 브라우저에 남습니다.
- `내 데이터 삭제` 버튼으로 언제든 전부 지울 수 있습니다.
- **학생 개별 데이터는 절대 이 GitHub 저장소에 커밋하지 마세요.**

## 8. 진단이 하는 일 / 하지 않는 일

**하는 일** — 붙여넣은 기록에 실제로 존재하는 표현만 근거로, 학업역량·진로역량·공동체역량 3축의
강점과 보완점을 제시하고, 학교 편제에 비추어 "이 학교에서 가능한 최선의 선택을 했는가"를 해석합니다.
기록에 남은 활동을 한 단계 심화한 탐구 주제를 제안합니다.

**하지 않는 일** — 합격 가능성 예측, 대학별 당락 판단, 기록에 없는 활동·수상·성적의 생성.

> 진단 엔진은 브라우저에서 도는 **규칙 기반**입니다. 외부 AI API를 호출하지 않으므로
> 생기부 원문이 어디로도 나가지 않습니다. 더 정밀한 서술형 평가가 필요하면
> 서버리스 프록시를 두고 AI 평가 계층을 붙이는 방식(마스터 프롬프트 4-A안)으로 확장할 수 있습니다.
> API 키는 절대 클라이언트 코드에 넣지 마세요.

## 10. 자주 나는 오류

| 증상 | 원인과 해결 |
|---|---|
| 화면에 "데이터를 불러오지 못했습니다" 배너 | `index.html`을 더블클릭해서 열었을 가능성이 큽니다. 2번 항목대로 정적 서버로 여세요. |
| 특정 학교만 안 열림 | 그 학교 JSON의 문법 오류입니다. 배너에 이유가 표시됩니다. `node tools/validate.mjs`로 확인하세요. |
| 과목이 화면에 안 보임 | `category` 값이 네 가지(공통과목/일반선택/진로선택/융합선택) 중 하나가 아닌지 확인하세요. |
| 학교 목록에 새 학교가 없음 | `regions.json`에 등록하지 않았습니다. 3번-② 참고. |
| 성취도 막대가 이상함 | A~E 비율의 합이 100%가 아닙니다. 검증 스크립트가 경고로 잡아 줍니다. |

## 11. 버전

- `schemaVersion: "4.0"` — 데이터-코드 분리, 지역 계층 + 지연 로딩, 학년 분기, 생기부 진단, 리포트 출력
- `schemaVersion: "4.1"` — 과목 단위 성취(`subjectAchievement`), 참조 바스켓 비교(`metrics` + `reference-groups.json`),
  학점배당표 편제(`creditPlan`), 세부 학과 주제 풀(`programs/`), 진단 보완점의 설계 반영, 공동교육과정 과목 직접 추가
  - 4.0 데이터는 그대로 동작합니다. 새 필드가 없으면 해당 화면만 "미입력"으로 표시됩니다.
- 데이터 형식이 바뀌면 이 항목에 마이그레이션 안내를 남깁니다.

## 12. 아직 만들지 않은 것 (다음 단계 후보)

- B2C / B2B 에디션 분리 빌드 (`editions/*.json` + 빌드 스크립트)
- 학과 확대 (현재 의예과·반도체공학·경영학·사회학 4개). 나머지 학과는 화면에 "준비 중"으로 표시됩니다
- 학점배당표 편제 확대 (현재 휘문·중동·은광여·숙명여 4개교)
- 탐구 자료 과목 확대 (현재 10개 과목)
- 전국 지역 확대 (구조는 준비 완료, 학교 JSON만 추가하면 됨)
